## 1. 信息架构

### 1.1 一级导航只有 4 项

```
┌────────────────────────────────────────────────────────────┐
│  顶栏 52px：作品切换器（全局唯一） │ 面包屑 │ 模型状态灯      │
├──────┬─────────────────────────────────────────────────────┤
│ 56px │                                                     │
│ 图标 │                    内容区                            │
│ 栏   │                                                     │
│ ✍️   │                                                     │
│ 🆕   │                                                     │
│ 📚   │                                                     │
│ ⚙️   │                                                     │
└──────┴─────────────────────────────────────────────────────┘
```

| 导航 | 路由 | 职责 |
|---|---|---|
| ✍️ 写作 | `/` | 章节树 \| 纸感编辑区 \| 上下文面板（5 Tab） |
| 🆕 开新书 | `/new` | 种子 → 剧情 → 大纲与人物（三步向导） |
| 📚 素材库 | `/library` | 作品 / 灵感 / 导入（三 Tab） |
| ⚙️ 设置 | `/settings` | LLM 与密钥 / 数据与备份 / AI 增强 / 外观（四分区） |

**设计决策：按"作者要干的事"切分，不按"技术模块"切分。**

早期版本把导航按模块切成 6 项（灵感园 / 创作 / 质检 / 作品库 / Skills / 设置），
每个动作都要重新选作品、重新找入口。现在收敛成 4 项，主流程从 5 步缩到 2 步。

### 1.2 人物 / 大纲 / 版本降级为侧栏面板

这三者都是**「当前章节的上下文」**，不是独立页面 —— 独立成页会导致：

- 换章节要重新切页面
- 上下文（人物卡、大纲）离正文太远
- 章节树在多个页面重复实现

现在统一收进写作页右栏的 5 个 Tab。

### 1.3 作品选择器是全局唯一状态

`stores/workspace-store.ts`，持久化到 localStorage。

**顶栏的切换器是全应用唯一的作品入口。** 禁止在任何页面再放第二个作品下拉 ——
历史上重复过 3 处，切页面就丢。`/creation`、`/skills` 这些旧路由
现在都是 `Navigate` 重定向（见 `App.tsx`）。

### 1.4 写作页右栏 5 个 Tab

| Tab | 职责边界 |
|---|---|
| 生成 | 整章流式生成 |
| 重写 | **选区**替换（没选区时按钮禁用） |
| 人物 | 当前作品人物卡 |
| 大纲 | 结构化渲染 + 一键拆章 |
| 版本 | 历史 + diff + 回滚 |

> 2026-10-30 原第 3 个 Tab 是「质检」，随质检模块整体下线而移除。
> 现在的 5 个 Tab 全部是**「当前章节的上下文」**，没有一个是独立功能页。

### 1.5 素材库作品卡的右键菜单

作品卡提供**三种等价入口**（照顾不同习惯，也照顾键盘用户）：

| 入口 | 说明 |
|---|---|
| 右键卡片 | 系统惯用菜单 |
| 卡片右上角 **「⋯」** | 悬停时可见，给鼠标用户 |
| `Shift+F10` / `ContextMenu` 键 | 聚焦卡片后的键盘路径 |

菜单项：**重命名 / 删除 / 上移 / 下移 / 导出**。

**排序**在列表上方的下拉里选：**手动顺序 / 最近更新 / 最近创建 / 字数最多 / 按书名**。

> 「手动顺序」记在服务端（`novels.sort_order`），关掉应用再进来还在。
> 选了其它排序方式后又点「上移 / 下移」，会自动切回「手动顺序」并提示 ——
> 否则看着像「点了没反应」。

## 2. 视觉规范（实测值）

> 以下数值全部来自 `apps/desktop/src/styles.css` 与各组件的 class，
> **不是**设计提案里的数值（2026-10 的设计提案曾规划过一套品牌靛蓝/AI 紫令牌，
> 但最终实现未采用 —— 实际用的是 shadcn/ui 默认的 zinc 灰阶 + 少量强调色）。

### 2.1 颜色令牌

主题走 shadcn/ui 的 HSL CSS 变量（`styles.css` 的 `:root` / `.dark`）。

| 令牌 | 浅色 | 深色（默认） | 用途 |
|---|---|---|---|
| `--background` | `0 0% 100%` | `240 10% 3.9%` | 应用最外层 |
| `--foreground` | `240 10% 3.9%` | `0 0% 98%` | 主文字 |
| `--card` / `--popover` | `0 0% 100%` | `240 10% 3.9%` | 卡片 / 浮层 |
| `--secondary` / `--muted` / `--accent` | `240 4.8% 95.9%` | `240 3.7% 15.9%` | 次级面 |
| `--muted-foreground` | `240 3.8% 46.1%` | `240 5% 64.9%` | 次要文字 |
| `--primary` | `240 5.9% 10%` | `0 0% 98%` | 主按钮 / 选中态 |
| `--border` / `--input` | `240 5.9% 90%` | `240 3.7% 15.9%` | 1px 分隔线 |
| `--destructive` | `0 84.2% 60.2%` | `0 62.8% 30.6%` | 删除 / 失败 |
| `--ring` | `240 5.9% 10%` | `240 4.9% 83.9%` | 焦点环 |

**强调色**（少量使用，非系统级令牌）：

| 颜色 | 用途 | 出现处 |
|---|---|---|
| `indigo-500` / `indigo-600` | 顶栏模型灯、导航选中态、focus ring | `app-shell.tsx` |
| `violet-100` / `violet-900` | 人物卡「队友」关系标签 | `CharacterCard.tsx` |
| `purple-100` / `purple-700` | 版本来源「已导入」标签 | `version-panel.tsx` |

> 界面主体用 `neutral-*`（58 处），强调色只在少数状态位出现。
> 语义分工没有做成系统级令牌 —— 想加新颜色时，先在组件里确认确实需要。

### 2.2 纸面编辑区（`.novel-paper`）

**固定浅色纸面，不随主题切换** —— 长时间写作不刺眼。
深色主题下是「深色外壳 + 浅色纸面」（Ulysses / 思源笔记的思路）。

| 属性 | 值 |
|---|---|
| 背景 | `#faf8f3` |
| 正文色 | `#2b2723` |
| 引用块左边线 | `3px solid #d8d2c6`，文字 `#6b6459` |
| 占位提示色 | `#a79e91` |
| 选区 | `#e3e8fb` |
| 阴影 | `0 10px 34px rgba(0,0,0,.18), 0 1px 2px rgba(0,0,0,.08)` |

**跟随主题模式**（设置 → 外观 → 编辑区 → 跟随主题）：整块换成 `hsl(var(--card))`，
由 `html.paper-follow-theme` 切换。

### 2.3 尺寸

| 元素 | 规格 | 来源 |
|---|---|---|
| 顶栏 | 52px | `app-shell.tsx` |
| 图标栏 | 56px | `app-shell.tsx` |
| 章节树 | **244px** | `pages/Writing/chapter-tree.tsx` |
| 上下文面板（右栏） | **332px** | `pages/Writing/context-panel.tsx` |
| 圆角基数 `--radius` | 8px（`lg`） | `styles.css` |
| 间距基数 | 4px（Tailwind 默认） | — |

> ⚠️ 设计提案里写的是「章节树 240px / 右栏 320px」，实现时调成了 244 / 332。
> **以本表为准。**

### 2.4 字体

| 用途 | 字体栈 |
|---|---|
| 界面 | 系统字体栈（未指定，走 Tailwind 默认） |
| 正文（`.novel-editor-content`） | `"Noto Serif SC", "Source Han Serif SC", "Songti SC", "SimSun", serif` |
| 等宽（模型名 / 字数） | JetBrains Mono（编辑器状态栏） |

正文排版：`font-size: var(--novel-font-size, 16.5px)`，`line-height: 1.95`，
`letter-spacing: 0.01em`，`text-align: justify`。
中文正文用衬线体（长篇阅读更耐看），且**必须**两端对齐 —— 渲染器只在拉丁词之间拉伸。

### 2.5 滚动条

深色模式下系统默认滚动条是**亮白色**，在深色背景上刺眼（用户 2026-10-24 反馈）。
已自绘：深色用近黑滑块 `#3f3f46`（hover `#52525b`），浅色用 `hsl(var(--border))`。
`::-webkit-scrollbar`（WebView2）+ `scrollbar-color`（Firefox）双写。

### 2.6 动效

| 场景 | 时长 | 缓动 |
|---|---|---|
| 面板折叠 | 180ms | `cubic-bezier(.4,0,.2,1)` |
| 步骤切换（向导） | 240ms 横向位移 12px | 同上 |
| 流式文本 | 逐字 16ms 节流 | linear |
| 卡片 hover | 120ms | ease-out |

### 2.7 正文排版规则（2026-10-30 新增）

正文不是「模型给什么就显示什么」—— 后端 `core/prose_format.py` 做**增量排版**，
前端 `lib/prose-insert.ts` 决定插入位置。

| 规则 | 实现 |
|---|---|
| 汉字之间的空格删掉 | `normalize_whitespace`（英文单词之间的**保留**） |
| 模型给的 `\n` → 段落分隔 | `split_paragraphs` |
| **兜底断段**（模型不给段落时） | 段落 ≥30 字遇句末标点 `。！？…` 就断 |
| 段落过长（>120 字） | 允许在弱断点 `，、；：` 断开 |
| 对白收尾后另起一段 | 多人对话能分辨谁在说话 |
| **连续对白强制断段** | `“甲？”“乙。”` → 两段；但 `将“沈”“砚”二字` **不拆**（引用不能拆断） |

**字数口径 = 非空白字符数**（含中文标点，不含空格 / 换行）。
与 Word 的「字数」、网文平台（起点 / 番茄）一致。
**前端与后端必须完全一致** —— JS 的 `\s` 不匹配全角空格 U+3000，要单独覆盖。

**插入位置 = 最后一个段落内部**，不能在文末 `insertText`（后者每次 flush 新建一个段落，
1012 个假段落把 3314 字撑成 5338 字）。

详见 [PROJECT_STRUCTURE.md](./PROJECT_STRUCTURE.md) §5.4。

## 4. 改 UI 时的规矩

1. **改动前先读本文件 + `AGENTS.md` §2.1** —— 硬约定在那里
2. **数值改动要同步本文件** —— 本表的每个数字都对应源码里的一处 class
3. **改了导航 / 页面结构 / 按钮文案，同一个 commit 内同步** `README.md`、
   `docs/PROJECT_STRUCTURE.md`、`docs/USER_GUIDE.md`、`docs/START_GUIDE.md`
   （`AGENTS.md` §2.2 有这条硬要求）
4. **新截图放 `docs/screenshots/`**，命名 `NN-页面-主题.png`
5. **不要引入设计提案里的品牌色板** —— 除非同时改 `styles.css` 的令牌，
   并更新本文件 §2.1
