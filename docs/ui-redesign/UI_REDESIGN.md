# Book Soul · UI 重设计提案

> 版本 v1.0 · 2026-10-23
> 范围：前端信息架构、页面结构、流程动线、视觉规范
> 产物：`prototype.html`（15 屏高保真原型）+ `screenshots/`（设计图）
> 依据：现状代码实读（`apps/desktop/src/` 全量）+ 后端 API 全集（`server/src/api/`）

---

## 0. 一句话结论

现有功能**不缺**，但**散**：53 个后端端点、12 个前端组件里有 **3 个是死代码**，一级导航按"模块"切分而不是按"作者要干的事"切分，导致用户每做一个动作都要重新选作品、重新找入口。

重设计方向：**把 6 个平铺页面收敛成 4 个，把质检/人物卡/大纲从"独立页面"降级为"当前章节的侧栏面板"，把作品选择器提升为全局顶栏状态**。功能一个不少，但主流程从 5 步缩短到 2 步。

## 2. 问题诊断（10 条，按严重度排序）

### P0 · 功能可见性断裂

**① 人物卡没有界面——项目的核心特色是死的**

`CharacterCard.tsx`（人物卡展示卡）和 `CreateCharacterDialog.tsx`（新建/编辑人物卡）在整个 `apps/desktop/src/` 里**没有任何页面 import**：

```
grep '^import .*(CharacterCard|CreateCharacterDialog)' apps/desktop/src → 0 命中
```

只有 `CharacterGrowthDialog` 被 `CharacterCard` 引用（死代码引用死代码）。
后果：灵感园生成的人物卡，用户**看不到内容、改不了、加不了**。全书最核心的一致性资产被生成后就丢弃了。

**② 大纲不可读、不可编辑**

`LibraryDetail.tsx:220` — 大纲渲染为 `JSON.stringify(outline.structure, null, 2)`。作者看到的是裸 JSON。且 `outlinesApi.patch` 后端已就绪，前端从未调用。

**③ "新建作品"是死按钮**

`Library/index.tsx:38` — 点击后 `toast.info("敬请期待")`。后端 `POST /novels` 已存在，前端 `novelsApi` 未接。

### P1 · 信息架构错位

**④ 导航按"开发模块"切，不按"作者任务"切**

`质检` 是一级页面，但它处理的对象是**某一章**——天然属于创作上下文，不该和"创作"平级。

**⑤ 作品选择器重复实现 3 处**

`Creation/NovelSelector.tsx` 和 `QualityCheck/index.tsx:176` 各写一遍"作品下拉"，`Library` 又是第三处。用户每次换页面都要重新选作品，且**没有全局记忆**——切去质检会默认选中"第一个作品"，可能正是他不想检的那本。

**⑥ "藏书馆"与"作品"是同一列表**

`LibraryList` 传 `withChaptersOnly` 参数切两份数据，唯一区别是有没有章节。对作者而言这是同一个概念列表，应合并为一份 + 状态标签。

### P2 · 交互与冗余

**⑦ 灵感园流程起点是空转的欢迎页**

`WelcomeView` 占据整屏（`min-h-[60vh]`）只有一个按钮。首次用户的真实需求是"打开我上次写的书"，而不是"从零开始"。

**⑧ 底部 ChatInput 在完成步骤变成死界面**

`Inspiration/index.tsx:441` — `step === "done"` 时 placeholder 显示「（已完成；后续可去创作页继续）」，输入框仍可输入但无任何作用。

**⑨ 导出按钮重复两处**

`LibraryList.tsx:75` 与 `LibraryDetail.tsx:97` 各自实现了一遍导出逻辑。

**⑩ Skills 页是开发者视角，不该占一级导航**

展示"内置 / 已预装 / 后处理 / 需 LLM"这类实现细节，而普通作者只想知道"AI 会不会自动帮我做敏感词检查、字数统计"。应降级进设置。

## 3. 删改建议总表

| # | 现状 | 建议 | 理由 |
|---|---|---|---|
| 1 | 6 个一级导航 | **收敛为 4 个**：写作 / 开新书 / 素材库 / 设置 | 任务导向，非模块导向 |
| 2 | 质检 = 一级页面 | **降级**为写作页右栏「质检」Tab | 它是章节级操作 |
| 3 | Skills = 一级页面 | **降级**为设置 →「AI 增强」分区 | 开发者视角 |
| 4 | 作品库 4 Tab | **合并**为素材库 3 Tab：作品 / 灵感 / 导入 | 藏书馆与作品重叠 |
| 5 | 作品下拉 × 3 处 | **提为顶栏全局状态**，切换一次全站生效 | 消除重复选择 |
| 6 | 欢迎页 | **换成「最近作品」仪表盘** | 用户想续写，不是从零开始 |
| 7 | 人物卡无界面 | **写作页右栏加「人物」Tab**，卡片可展开编辑 | 核心特色必须可见可改 |
| 8 | 大纲显示裸 JSON | **右栏加「大纲」Tab**，结构化渲染 + 可编辑 | 可读性 + 可编辑 |
| 9 | 章节大纲只能建章节时填 | 大纲 Tab 支持**一键拆章** | 从大纲到正文的断点 |
| 10 | 「新建作品」死按钮 | **实现**（后端已就绪） | 死按钮必须消灭 |
| 11 | 无 LLM 连接测试 | 设置页加「测试连接」按钮（`/llm/test` 已就绪） | 排障必需 |
| 12 | 数据目录只读 | 加「打开数据文件夹」按钮 | 便携模式的价值点 |
| 13 | 导出逻辑重复 | 收敛到 `useNovelExport` hook | DRY |
| 14 | ChatInput 在 done 步骤仍显示 | **状态驱动显隐**，无效步骤不渲染 | 消灭死界面 |
| 15 | 备份在设置页中段 | 移到「数据与备份」分区，与数据目录同组 | 信息架构归位 |

**没有建议删除的功能。** 53 个后端端点全部保留可达。

├────────┬────────────────────────────────────────┬────────────────────┤

│        │                                        │   320px            │
│ ✍ 写作 │   章节树  │      编辑器 / 报告 / 向导      │   可折叠            │
│ ✦ 开新书│            （随路由变化）                 │                    │
│ ▦ 素材库│                                        │                    │
│ ⚙ 设置 │                                        │                    │
└────────┴────────────────────────────────────────┴────────────────────┘

### 4.1 四个一级页面

| 路由 | 名称 | 职责 | 主区内容 | 右栏面板 |
|---|---|---|---|---|
| `/` | **写作** | 日常主战场 | 章节树 + 编辑器 | 6 个 Tab：生成 / 重写 / 质检 / 人物 / 大纲 / 版本 |
| `/new` | **开新书** | 3 步向导 | 步骤内容（单列居中） | —（底部固定「想法输入」） |
| `/library` | **素材库** | 资产归档 | 作品 / 灵感 / 导入 三 Tab | 详情抽屉 |
| `/settings` | **设置** | 配置 | 4 个分区 | — |

### 4.2 顶栏 = 全局上下文条

顶栏承担三件事，其他任何页面都不再重复：

1. **作品切换器**（常驻）— 切换后写入 Zustand `workspaceStore`，全站生效并持久化
2. **当前位置面包屑** — `作品名 › 第 N 章 · 标题`
3. **模型状态灯** — `MiniMax-M3 ●` 绿点=正常 / 黄点=降级 / 红点=不可用，点击进设置

### 4.3 写作页三栏

```
┌─────────────┬───────────────────────────────┬──────────────────┐
│ 章节树      │  第 12 章 · 夜雨               │  [生成][重写]    │
│ 240px       │  ┌─────────────────────────┐  │  [质检][人物]    │
│             │  │                         │  │  [大纲][版本]    │
│ ▾ 第一卷    │  │      Tiptap 编辑器      │  │                  │
│  ▪ 第10章   │  │      纸感浅色区          │  │  ─────────────   │
│  ▪ 第11章   │  │                         │  │  正文提示词      │
│ ▸ 第12章 ●  │  │                         │  │  [输入…]        │
│  ▫ 第13章   │  └─────────────────────────┘  │  [生成正文]      │
│             │  1,842 字 · 已保存 v3          │                  │
└─────────────┴───────────────────────────────┴──────────────────┘
```

**关键改动**：编辑区用**浅色纸感底**（`#faf8f3`），外壳深色。长时间写作不刺眼，同时保留桌面工具的专业感。

### 4.4 右栏 6 个 Tab 的职责边界

| Tab | 内容 | 入口 |
|---|---|---|
| **生成** | 目标字数、补充要求 → 流式写正文 | 顶部「生成」按钮 |
| **重写** | 显示当前选区字数 + 重写指令 → 替换选区 | 选中文字后按钮自动亮 |
| **质检** | 5 维评分 + 雷达图 + 问题列表；**每条问题可一键「重写这段」** | 顶部「质检」按钮 |
| **人物** | 本书人物卡列表（角色/关系/成长线），点击展开编辑 | 顶部「人物」按钮 |
| **大纲** | 结构化大纲（卷 → 章 → 冲突/钩子），可编辑，**一键拆章** | 顶部「大纲」按钮 |
| **版本** | 版本树 + diff 对比 + 回滚 | 顶部「版本」按钮 |

> **质检 → 重写闭环**是本次重设计新增的关键动线：质检发现问题 → 点「重写这段」→ 自动带着问题描述进入重写 → 完事回到质检页看新分数。问题不留在报告里，而是被修掉。

## 5. 流程动线

### 动线 A · 从零开一本新书（主线）

```
开新书
  │
  ├─[步骤 1] 种子 ─────────────────────────────────────┐
  │   题材 4 选 1 → 词库候选池点选 → 自定义输入         │
  │   底部「想法输入」随时补充                        │
  │   【下一步：生成 3 个剧情】                        │
  │                                                    │
  ├─[步骤 2] 剧情 ────────────────────────────────┐    │
  │   3 个版本并排流式渲染（各自独立进度）          │    │
  │   鼠标悬停/点击卡片放大阅读                     │    │
  │   【选中一个 → 下一步】                         │    │
  │                                                 │    │
  └─[步骤 3] 大纲 + 人物 ────────────────────┐     │    │
      大纲结构化流式生成（卷/章/冲突/钩子）   │     │    │
      ↓ 立即切到人物卡                          │     │    │
      从大纲抽取角色 → 逐张人物卡流式生成      │     │    │
      ┌────────────────────────────────┐       │     │    │
      │ ✓ 大纲已生成  ✓ 6 张人物卡      │       │     │    │
      │ 【去写第一章 →】               │───────┘     │    │
      └────────────────────────────────┘             │    │
                                                       └────┘
                                     ↓ 自动切到写作页 + 自动建第一章
```

**与现状的差异**：完成页从"居中一个对勾"改为**带产出的确认卡**（大纲摘要 + 人物卡头像行 + 直接进写作页），并**自动创建第一章**（承接大纲第一章），消除"到了写作页还要再点新建章节"的二次断点。

### 动线 B · 日常续写（主线 · 最高频）

```
打开应用 → 顶栏显示上次作品 + 上次章节（已记忆）
   → 写作页直接停在那个章节、那个光标位置
   → 右侧「生成」→ 输入本章要点 → 流式出正文
   → 边读边改，Ctrl+Z 撤销
   → 满意 → 右栏「质检」→ 看 5 维分
       → 发现文笔问题 → 点「重写这段」→ 指令自动带入 → 重写
       → 分数上升 ✅
   → 右栏「版本」→ 对比 v2/v3 → 回滚到喜欢的版本
```

### 动线 C · 资产归档

```
素材库
 ├─ Tab 作品：卡片列表（封面占位 / 题材 / 进度环 / 状态标签 / 字数）
 │    ├─ 点卡片 → 抽屉：章节 / 人物 / 大纲 / 导出(md/html/docx)
 │    ├─ 悬停 → 「继续写」→ 切到写作页
 │    └─ 右上「新建作品」→ 弹窗（名称/题材/简介）→ 建空作品
 ├─ Tab 灵感：灵感卡列表（可搜/可筛/可收藏）
 │    └─ 点开 → 抽屉详情 → 「用这个灵感开新书」
 └─ Tab 导入：选目录 → 扫描结果表 → 勾选 → 导入
```

### 动线 D · 首次配置（冷启动）

```
启动 → 握手失败 → 启动屏给真实原因 + 日志路径
     → 成功 → 若未配置 Key，右栏常驻黄色横幅：
        「还没有配置 API Key · 去设置」
启动 → 设置 → LLM 与模型 → 填 Key → 点【测试连接】
     → 绿点亮 + 显示「延迟 812ms / 上下文 200k」
     → 顶栏模型灯变绿 ✅
```

### 12.3 顺带修掉的五个真实缺陷

1. **保存版本会抹掉原有正文**（旧创作页就有）
   生成是**追加**、重写是**替换选区**，两种情况下流式累积量都不是完整正文。
   旧实现直接存累积量 → 章节原有内容丢失。
   修法：`pickSavedContent()` —— 流式结束后取编辑器全文落库（有测试锁住）。

2. **大纲只能看不能改** —— 后端 `PATCH /novels/{id}/outlines/{id}` 一直就绪但前端从未调用。

3. **普通 API 请求在纯浏览器模式下全挂**（`pnpm dev` 单独跑时）
   流式端点（`readNdjsonStream`）本来就是 `fetch` 直连后端，普通请求 `callApi` 却只走
   Tauri `invoke` —— 两套机制不一致。后果：`pnpm dev` 单独跑时页面能连上后端，
   却一个数据都拿不到（作品列表空、"最近的作品"不显示、模型状态显示"未连接"）。
   修法：`callApi` 增加**浏览器通道**（`fetch` 直连，复用 `getBackendUrl()` 已有的
   DEV_FALLBACK）；桌面版在 Tauri 运行时里行为完全不变。后端 CORS 早已放行 5173。

4. **模型列表把所有模型误标「服务端已下线」**
   `offline = !live_models.includes(m)`。但 `live_models` 为空（没配 Key / 401 / 没刷新）
   时**无从判断是否下线**，结果所有模型都被标成已下线。
   修法：`live_models` 非空才判定；同时在列表下方说明真实原因（拿不到清单 / Key 无效）。

5. **主题、纸面模式、正文字号重启后全部丢失**
   - 主题写进了后端 `ui.theme`，前端却**从不读**（uiStore 硬编码默认 dark），
     也没有持久化 → 设置页点「保存」后重启还是深色。
   - 纸面模式 / 字号只存在设置页组件的 useState 里，组件卸载即丢；
     `paper-follow-theme` class 还只在点击时加 → 重启后界面显示"跟随主题"、
     实际 DOM 没跟随。
   修法：新增 `stores/appearance-store.ts`（纸面模式 + 字号，localStorage 持久化），
   `uiStore` 加 persist，**由 AppShell 统一在启动时把值应用到 DOM**
   （class + CSS 变量），并读后端 `GET /settings` 的 `ui.theme` 覆盖本地值。
   顶栏的主题切换按钮改为「立即生效 + 顺手落盘」，不再需要手动点保存。

另外顺手打磨：素材库作品卡封面原本用硬编码 emoji（⚔️/📖/📕）当视觉主体，
Windows 下渲染又大又花 → 改成**书名首字 + 渐变底**，与顶栏/空态的缩略图一致。

### 12.7 第三轮：流式体验 + 性能定位（2026-10-24）

用户实测报的问题：滚动条刺眼 / 剧情顺序乱 / 选项框看不到后面的内容 /
流式"卡一下再一口气吐" / 生成慢。逐条定位如下。

#### 1. 深色模式滚动条（刺眼的白条）

深色模式下系统默认滚动条是**亮白色**，在深色背景上很扎眼。
改为自己画：深色用**近黑**滑块（`#3f3f46` / hover `#52525b`），浅色用中性灰。
`apps/desktop/src/styles.css`（同时写了 Firefox 的 `scrollbar-color`）。

#### 2. 剧情生成顺序（C → A → B）

三个版本**并行**调用 LLM，谁先回是随机的 → 屏幕上是 C 先出字。
改用 `merge_queue_events_ordered`：**生产者仍然并行**（总耗时不变），
只把吐事件的顺序固定成 A → B → C。

#### 3. 选项框看不到后面的内容（**根因**）

内容区写的是 `h-[212px] overflow-hidden`（固定高 + 裁切）：

- 文字流到 212px 就被裁掉 → 后面的字**渲染了但看不见**
- 结束时 `version_done` 一次性替换全文 → 又变成"一口气全出来"

所以问题 3 和问题 4 是**同一个根因**。改成 `max-h-[212px] overflow-y-auto`
+ **自动滚到底部**（只在用户本来就在底部附近时才自动滚，不打断回看）。

#### 4. 流式"卡住"的另一半：思考期空窗

推理模型先吐 `<think>...</think>` 再吐正文，思考可能好几秒。
旧代码 `if "<think>" in delta: continue` 把这段**全丢了** →
那段时间前端一个字都收不到 → 用户看到"卡住不动"。

新增 `core/llm/streaming.py::ThinkSplitter`（状态机，能处理 think 块被拆到
多个 chunk 的情况），把思考内容作为 **`thinking` 事件**转发给前端 →
前端显示"模型思考中…"+ 已耗时秒数。

剧情 / 大纲 / 人物卡三处生成器都换成了这个共享实现（原来同样的逻辑抄了 4 遍）。

#### 5. 性能定位：**慢在模型，不是我们的代码**

搭了一个本地 mock OpenAI 兼容 SSE provider（已知吐字节奏），指到真实后端上，
逐行测量 ndjson：

| 指标 | 实测 | 结论 |
|---|---|---|
| TTFB（HTTP 头） | 53 ms | 没有 HTTP 层缓冲 |
| 第一个事件 | 74 ms | 立即返回 |
| 每 token 间隔 | 50.6 ms（mock 是 50 ms） | **代码侧开销 +0.5 ms/token** |
| 整条流总开销 | ~100 ms / 2000 字 | 可忽略 |

**所以流式链路不是瓶颈** —— 总时长 = 模型思考时间 + 输出 token 数 ÷ 模型吐字速度。
优化路径：

| 手段 | 状态 |
|---|---|
| 换更快的模型（`mimo-v2.6-flash` / `ultraspeed` / minimax） | 设置页直接切 |
| 场景级 `max_tokens` 上限（防模型超写，生成时间与输出长度成正比） | ✅ 已加 `scene_limits.plot_generation` |
| Ollama base_url `localhost` → `127.0.0.1`（省 250ms 的 IPv6→IPv4 等待） | ✅ 已改 |
| 思考期不再空窗（`thinking` 事件） | ✅ 已做 |
| 埋点：日志里直接看 `first delta after Xs` / `N deltas, Xs total` | ✅ 已加 |

> 探针本身也暴露了两个真 bug：
> ① `Path(pkg.__path__)` —— 包的 `__path__` 是**列表** → `load_all_skills()` 崩 →
>    **用户自定义 skill 一个都加载不了**（内置的还在，因为它们在
>    `skills/__init__.py` 里显式注册，所以一直没被发现）。
> ② `asyncio.to_thread(load_all_skills)` 在线程里跑，app 停得比它快时
>    会往**已关闭**的 event loop 投递回调 → 线程里抛 "Event loop is closed"。

#### 新 bug ①：点剧情卡"点了没反应"

`onChoose` 里写的是 `setChosenPlotIdx(idx); void startOutlineStream();`。
但 **`setState` 是异步的** —— 同一帧里 `startOutlineStream` 读到的 `chosenPlotIdx`
还是 `null`（第一次点）或**上一次的值**（第二次点）。

后果：

- 第一次点卡片 → 直接 `return`，**什么都不发生**（用户以为功能坏了）
- 先点 A 再点 B → 生成的是 **A 的大纲**（选 B 生成 A）

修法：卡片只负责"选中"，生成走按钮并**显式传索引**
（`startOutlineStream(chosenPlotIdx)`）。同时给大纲步骤加了
**「← 换一条剧情」**返回入口 —— 否则选错了只能整本重开。

> 推广规则见 AGENTS.md §4.9。

#### 新 bug ②：人物卡并行入库炸 session

日志里稳定出现：

```
card 林晚 failed: LLM call failed: InvalidRequestError: Session is already flushing
card 赵屿 failed: ...
card 陈默 failed: ...
```

4 张人物卡的 **LLM 调用是并行的**（对），但**入库也是并行的**（错）。
所有卡共用同一个 `AsyncSession`，而 `AsyncSession` 不是并发安全的 ——
同时 `flush()/commit()` 就炸。

实测结果：**4 张卡只存进去 1 张**，而前端 toast 还报"已生成 4 个人物卡"。

修法：**并行留给 LLM 调用，写库用 `asyncio.Lock` 串起来**（`db_lock`）。
非流式路径一直是对的（先 `gather` 再 for 循环入库），只有流式路径漏了。
同时把 `saved_count` 改成**按实际入库张数**统计，不再报计划张数。

回归测试用 `asyncio.Barrier` 让所有卡同时进入入库阶段，**确定性复现**这个竞态
（去掉修复 → 测试变红；装回修复 → 全绿）。

> 推广规则见 AGENTS.md §4.8。

#### 顺带：抽出公共的"自动跟随"规则

`plot-step` 和 `outline-step` 原来各抄了一份 `useEffect`（判断"用户本来在不在底部"
+ 滚到底）。抽到 `apps/desktop/src/lib/auto-scroll.ts`（纯函数，可单测），
并补了 9 条 vitest 用例 —— 改一处漏一处不会再悄悄回归。

#### 第四个真 bug：HTTP 层失败被静默吞掉 → 界面永久转圈

**现象**：大纲生成请求返回 **422**，界面却一直停在「流式生成中 …」，不报错也不回退。

**根因**：NDJSON 流有两种失败，长得完全不一样：

| 来源 | 事件形状 |
|---|---|
| transport（HTTP 非 2xx / 无 body / 解析失败） | `{ "error": "422 ..." }` ← 前端 `readNdjsonStream` 产出 |
| server（后端流内错误帧） | `{ "event": "error", "message": "..." }` |

`readNdjsonStream` 遇到 HTTP 错误时 `yield { error: detail }` —— **没有 `event` 字段**。
而开新书页三个流循环只判 `obj.event === "error"` → **永远不命中**：
generator 正常 `return` → `for await` 正常退出 → 没有任何分支命中 →
不弹错、不回退，界面永远转圈。

**修法**：抽出 `detectStreamFailure(ev)`（`apps/desktop/src/api/streams.ts`），
统一识别两类失败，三个流循环都改用它，识别到就 toast + 回退。

**为什么这个 bug 能活这么久**：写作页 `use-chapter-stream.ts` 早就在用 `isStreamError`，
**开新书页没抄**。同一种错误，一个页面处理了、另一个页面没处理。
所以新增流消费方时**照抄写作页，别照抄邻居**。

> 推广规则见 AGENTS.md §4.10。

#### 顺带：把 mock provider 修成"能真的走通三步"

原来的 mock 吐 `"字" * (MOCK_CHARS × MOCK_CHUNKS)`，本轮设成 260×40 = **10400 字**，
而后端 `plot_summary` 上限 5000 字 → 下一步大纲接口直接 422。三个问题：

1. **兜底内容封顶**（`MOCK_MAX_CHARS`，默认 4000）—— 未知场景不该把接口撑爆。
2. **加剧情分支**：真实 prompt 要 200-400 字，mock 也给这个量级；
   3 个版本轮换（`_VARIANT_COUNTER`），让三张卡内容不同，近似真实的多采样。
3. **先解析 JSON 再取 prompt**（`extract_prompt_text`）：请求体是 JSON，prompt 里的换行是
   转义的 `\n`（两个字符）。直接在原始 JSON 上按行切，会把"题材：xxx"后面一整条 JSON
   （包括 `"temperature":0.8`）当成题材值抠出来 —— 表现就是剧情卡里吐出一堆 JSON 片段。

前两条是"mock 不忠实"，第三条是**真 bug**（在 mock 代码里，但同样说明"从 JSON 里取文本"
必须先解析）。
